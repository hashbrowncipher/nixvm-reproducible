# VM time from measured execution

Updated the existing `nixvm-pmu` worktree from `2a50a3b` to local master
`b43db59`, then replaced guest host-clock reads with one shared `VirtualClock`
per VM. Monotonic time starts at zero; realtime uses the fixed Unix epoch
1700000000 seconds. One measured execution unit contributes one nanosecond.
KVM and the x86 interpreter count conditional branches, including solo
execution; the ARM interpreter counts retired instructions. Idle jumps and
clock-observation acceleration advance elapsed time without charging CPU time.
Repeated observations grow geometrically up to a bounded increment, share a
per-task streak across timestamp instructions and clock syscalls, and stop at
the next pending deadline.

The scheduler projects monotonic timer deadlines into execution limits and
combines them with the remaining fairness quantum when tasks compete. All
parked tasks permit a jump to the next timed event. KVM continuously counts
guest execution, uses early overflow followed by precise stepping, and credits
actual retired branches without subtracting skid. Automatic KVM selection now
requires a successful guest-only PMU probe; unavailable hardware falls back to
an interpreter. HVF remains experimental and is excluded from automatic
selection until it implements the clock contract. Measured execution currently
requires one scheduler CPU.

Timed futex, poll/select/epoll, signal, message and IPC waits use VM deadlines.
Expired futex registrations become terminal before a later wake; initial
value mismatch still wins over an expired initial timeout. Registered waitv
inputs survive retries. SA_RESTART preserves the original deadline through
the actual rt_sigreturn service path. CPU-domain POSIX timers exclude idle
and observation advances. Timerfd deadlines remain live through stopped
descriptor owners and queued SCM_RIGHTS references, and disappear when the
last usable reference closes. TmpFs and DevFs generated timestamps use the VM
clock. Passthrough filesystems intentionally retain host timestamps, including
timestamps generated by guest operations; an inline comment records that
decision beside metadata timestamp copying.

The syscall-return trampoline runs in ring 0. Beginning a precision tail at
SYSRETQ allowed restored R11 to clear the stepping flag. `set_syscall_ret`
now completes that known return in software before a newly armed timer can
start precision stepping. Asynchronous signal delivery also requires an
actual user boundary, preserving the interrupted user instruction pointer.

## Validation

The test-first commit `f755ce5` added two futex regressions before the fix.
Both failed against isolated baseline `b43db59`: a late wake reported one
wake after timeout, and an initial value mismatch returned ETIMEDOUT instead
of EAGAIN. Both pass with the implementation.

Final validation used Rust `1.93.1 (01f6ddf75 2026-02-11)`, Linux/x86-64,
the existing offline Cargo cache, and the parent's sealed network-isolated
runner. No dependency or lockfile changed. Results:

- Full `erofs,fstool` suite: 783 library tests passed, two existing manual
  corpus scans ignored; all integration and documentation tests passed.
- Explicit hardware suite: all 12 PMU cases and seven instruction-trap cases
  passed with ignored hardware tests enabled and one test thread. Hardware
  assertions compare PMU counts with guest loop registers and check the
  saved user RIP and independent progress when timers interrupt a task.
- Independent review: 13 focused virtual-time kernel regressions passed;
  source review approved the final clock, backend, wait and filesystem scope.
- Clippy passed for all targets with `erofs,fstool`, denying warnings and
  retaining the existing `field-reassign-with-default` allowance.
- Rust formatting through the parent's formatter helper and `git diff --check`
  passed.
- `wasm32-unknown-unknown --no-default-features --lib` compiled successfully.
  An earlier all-binary wasm check reached inherited host-only imports in
  development binaries; the supported library target was checked explicitly.

Equivalent validation commands, with `NIXVM_PARENT_TOOLS` naming the parent
checkout's tools directory and `CARGO_HOME` naming its existing cache:

```sh
python3 "$NIXVM_PARENT_TOOLS/sealed.py" cargo test --offline --locked --features erofs,fstool --quiet
python3 "$NIXVM_PARENT_TOOLS/sealed.py" cargo test --offline --locked --test pmu --test instruction_traps -- --include-ignored --test-threads=1
python3 "$NIXVM_PARENT_TOOLS/sealed.py" cargo clippy --offline --locked --all-targets --features erofs,fstool -- -D warnings -A clippy::field-reassign-with-default
python3 "$NIXVM_PARENT_TOOLS/sealed.py" cargo check --offline --locked --target wasm32-unknown-unknown --no-default-features --lib
```

The full test run used `tools/test.py` with an in-process standalone-crate
adapter: `layout.packages` returns no npm packages when package.json is absent,
and `offline.CARGO_TEST` selects the full Cargo command above. Formatting used
`tools/format.py` with a `layout.owner` fallback assigning root crate files to
`.`. These adapters leave parent tooling unchanged. Each operation was bounded
by 250 seconds.

## Delegation and remaining work

Three implementation agents and one independent reviewer used the inherited
Codex model configuration. Exact model identifiers, token counts and tool-use
counts were not exposed. Final integrated diff sizes, before this entry and
excluding the separately committed baseline regressions:

| Agent scope | Files | Added | Removed |
| --- | ---: | ---: | ---: |
| Clock/interpreters, scheduler tests and public docs | 10 | 843 | 298 |
| KVM/PMU and hardware tests | 6 | 419 | 224 |
| Kernel and filesystems | 18 | 1596 | 386 |
| Independent review | 0 | 0 | 0 |

These are primary ownership groups; public docs and integration fixes crossed
agent boundaries. The supervisor integrated, validated and committed the work.

Known limits remain explicit: an x86 loop without conditional branches cannot
consume an exact branch target; a host watchdog bounds only count-only KVM
execution and never supplies guest time. Guest PUSHFQ can observe precision
stepping's TF as before. Host watchdogs, embedder budgets and external I/O
remain separate from VM time. ITIMER_VIRTUAL/PROF and stored socket
send/receive/recvmmsg timeouts retain their inherited unsupported behavior.
Reaped-thread CPU totals can still disappear from process sums. Passthrough
host time is an intentional scope exception.

Ranked capital investments:

1. Give timer registrations an explicit lifetime authority. This removes
   descriptor-table and ancillary-reference scans and makes cancellation
   coverage easier to audit.
2. Define an execution metric and precision-debug policy that cover
   branch-free x86 code. This removes the remaining no-progress case and
   clarifies flags visible during exact stepping.
3. Teach parent package discovery about standalone root Cargo crates. This is
   a small investment before the next change and removes the repeated test
   and formatting adapters.
