## Findings and evidence

No confirmed or plausible actionable issue remains from this review.

- **Interpreter resolution and caller preservation:** `src/kernel/mod.rs:4506` reads PT_INTERP through `MountTable::read_file`, whose final-component symlink traversal resolves the full target before sizing/reading it (`src/fs/mount.rs:159`). Replacement loading precedes identity, handler, descriptor, timer, IPC, or shared-map mutations. Loader errors discard the temporary space and return before those mutations (`src/kernel/mod.rs:4525`). Missing interpreter returns ENOENT; loader failures preserve prior ENOEXEC semantics, with frame-pool Host failures translated to ENOMEM. The regression at `src/kernel/exec_tests.rs:53` exercises absolute and relative linker symlinks through both execve and execveat; `src/kernel/exec_tests.rs:92` checks memory, CR3, identity, handlers, and CLOEXEC descriptor preservation for missing/bad interpreters and malformed program headers.
- **Allocation cleanup:** `src/vcpu/mem.rs:1082` allocates a fresh root and scaffold using the existing physical pool and allocator. `AddrSpace::map` links partial interior allocations into the tree before returning exhaustion (`src/vcpu/pagetable.rs:212`); `new_exec` destroys that partial tree (`src/vcpu/mem.rs:1105`). An uninstalled private kstack frame is explicitly freed. `discard` consumes the abandoned space and destroys every reachable table/leaf (`src/vcpu/mem.rs:1132`, `src/vcpu/pagetable.rs:384`). Pinned scaffold frames survive destruction; shared ordinary frames decrement refcounts and survive while another mapping/owner exists (`src/vcpu/phys.rs:316`, `src/vcpu/pagetable.rs:448`). Lifecycle tests cover repeated staging/discard and staged setup exhaustion (`src/vcpu/mem.rs:1431`, `src/vcpu/mem.rs:1450`).
- **Shared memory, fork, IPC, and cache interactions:** replacement metadata starts empty and retains the sticky shared-space serialization flag (`src/vcpu/mem.rs:1113`). Old IPC attachments are detached using the old memory before its destruction (`src/kernel/mod.rs:4580`, `src/kernel/ipc.rs:215`). Writable shared-file mappings are flushed using old memory before replacement (`src/kernel/mod.rs:4586`). Old mappings then release their references, and page-cache GC examines the same allocator through the replacement (`src/kernel/mod.rs:4591`, `src/kernel/pagecache.rs:264`). Fork/vfork retain their existing distinct-space/refcount behavior. Existing CLONE_VM semantics are preserved; this patch does not implement Linux's broader multithreaded-exec semantics.
- **KVM invariants:** `new_exec` clones the existing PhysMem and allocator Arcs, preserving the memslot. Its root and private kstack are distinct while the old image remains live. `vcpu.reset` invalidates cached CR3 (`src/vcpu/kvm/vcpu.rs:1077`); the next run's `sync_cr3` refreshes both CR3 and cached private kstack PA (`src/vcpu/kvm/vcpu.rs:409`). No stale pool pointer is introduced by the replacement.
- **PMU signal lifecycle:** `src/vcpu/kvm/pmu.rs:520` disables the counter before draining. The wait set contains only reserved overflow signal 41, uses a zero timeout, retries EINTR, and ends on EAGAIN (`src/vcpu/kvm/pmu.rs:236`). HostScope acquisition blocks that signal before PMU setup; prepared confined workers keep it blocked, and KVM_RUN's mask temporarily permits delivery. On error paths, RunGuard's Drop body disables/drains before HostScope's field destructor restores the caller mask (`src/vcpu/kvm/pmu.rs:564`). On the successful path, the drained flag avoids a redundant drain after explicit host-mask restoration. The existing fixed signal-41 ownership convention remains unchanged.
- **Confinement scope and test meaning:** the added `rt_sigtimedwait` allowance permits consuming pending signals of the calling process and creates no file, process, or network capability (`src/confinement.rs:200`). Its subprocess regression genuinely crosses the installed filter (`src/confinement.rs:409`). Guard cleanup tests queue three real-time overflow notifications plus an unrelated signal, and verify overflow removal, unrelated-signal retention, and blocked-mask preservation (`src/vcpu/kvm/pmu.rs:583`). New hardware tests exercise repeated competing-task overflow and solo timer overflow across compute spans larger than the PMU skid reserve (`tests/confinement.rs:204`, `tests/confinement.rs:240`).
