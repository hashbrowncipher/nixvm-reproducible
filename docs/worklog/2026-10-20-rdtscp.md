# RDTSCP and randomness policy

Enabled RDTSCP in the fixed CPUID profile and KVM's existing #GP timestamp
emulation. It advances the same VM counter as RDTSC and syscall entry, returns
the timestamp in EDX:EAX, and zeroes RCX for a fixed TSC_AUX. The interpreter
already implements RDTSCP; its execution code is unchanged.

Documented RDRAND/RDSEED as working as intended in `docs/cpu.md`, linked from
README.md. Both remain hidden in CPUID. KVM faults both instructions; the
interpreter retains deterministic RDRAND and illegal RDSEED. No randomness
execution paths changed.

Validation on Rust 1.93.1:

- The full offline sealed suite passed: 768 passed, two existing ignored,
  7.22 seconds elapsed, through the established standalone test-tool adapter.
- Actual KVM tests covered mixed RDTSC/RDTSCP/syscall counter progression,
  blocked retries, fork/reset/new vcpu, zero-extended outputs, fixed TSC_AUX,
  flags, prefixes through 15 bytes, page boundaries and preemption.
- Interpreter RDTSCP execution and matching KVM/interpreter CPUID passed.
- The wasm32 library check, repository formatting check and `git diff --check`
  passed. The first mixed test incorrectly edited RCX during a pending SYSRET;
  it was corrected to initialize RCX in guest code before RDTSCP.
- Independent review was launched before the owner's requested checkpoint
  commit; its findings are recorded separately when complete.

Capital notes: the shared decoder and exception recovery made RDTSCP a small
extension. Timestamp boundary and flag tests now exercise both instructions,
which should make future clock changes cheaper to verify.
